# Понятно: сайт с сервером и Gemini

## Сдача на хакатон: Docker и запуск из командной строки

Проект написан на **Node.js**, не на Python. [requirements.txt](requirements.txt)
содержит все npm-библиотеки, включая транзитивные, и их точные версии из
`package-lock.json`. Python-зависимостей нет; устанавливать npm-пакеты через pip
не нужно. Воспроизводимая установка — `npm ci`, а не `pip install`.

### Собрать и запустить контейнер

Нужен Docker с поддержкой Linux-контейнеров. Команды выполняются из корня проекта:

```bash
git clone https://github.com/jauhau814-sudo/Poniatbo.git
cd Poniatbo
docker build -t ponyatno:hackathon .
docker run -d --name ponyatno -p 127.0.0.1:3000:3000 -v ponyatno-data:/app/data ponyatno:hackathon
curl http://localhost:3000/api/health
docker logs ponyatno
```

Открыть http://localhost:3000. SQLite хранится в постоянном томе `ponyatno-data`.
Остановить контейнер: `docker stop ponyatno`; снова запустить: `docker start ponyatno`.
Для пересоздания сначала остановить и удалить только контейнер командой
`docker rm ponyatno` — не удалять том с данными.

Без ключа доступны интерфейс, регистрация и учебные материалы; OCR и разбор
через нейросеть требуют действительного серверного ключа Gemini. Создайте `.env`
по `.env.example` и заполните `GEMINI_API_KEY` своим ключом. При создании контейнера
с настройками используйте вместо первого `docker run`:

```bash
docker run -d --name ponyatno --env-file .env -e HOST=0.0.0.0 -e PORT=3000 -e DB_PATH=/app/data/site.sqlite -e COOKIE_SECURE=false -p 127.0.0.1:3000:3000 -v ponyatno-data:/app/data ponyatno:hackathon
```

`COOKIE_SECURE=false` — только для локального HTTP. Для публичного HTTPS нужны
`COOKIE_SECURE=true`, `PUBLIC_ORIGIN` и обратный прокси. Реальный `.env` не включается
в Git и Docker-образ; ключ нельзя добавлять в Dockerfile или команду сборки.

### Скачать готовый Docker-образ без сборки

Готовый образ Linux/amd64 публикуется в [GitHub Releases](https://github.com/jauhau814-sudo/Poniatbo/releases)
после успешных тестов и HTTP-проверки контейнера в GitHub Actions. Скачать файлы
`ponyatno-docker-linux-amd64.tar.gz` и `SHA256SUMS` из одного релиза. Пример для Linux/Git Bash:

```bash
curl -fL -o ponyatno-docker-linux-amd64.tar.gz https://github.com/jauhau814-sudo/Poniatbo/releases/latest/download/ponyatno-docker-linux-amd64.tar.gz
curl -fL -o SHA256SUMS https://github.com/jauhau814-sudo/Poniatbo/releases/latest/download/SHA256SUMS
sha256sum -c SHA256SUMS
docker load -i ponyatno-docker-linux-amd64.tar.gz
docker run -d --name ponyatno -p 127.0.0.1:3000:3000 -v ponyatno-data:/app/data ponyatno:hackathon
```

### Запуск без Docker через командную строку

Нужен Node.js 24.5 или новее. В корне проекта:

```bash
npm ci
node scripts/export-requirements.mjs --check
npm test
npm start
```

Адрес тот же: http://localhost:3000. Остановка — Ctrl+C. Для функций ИИ сначала
создать и заполнить `.env` по `.env.example`; `npm start` подхватит его автоматически.
После изменения lockfile обновить список библиотек: `node scripts/export-requirements.mjs`.

## Запуск на Windows
Установите Node.js 24 LTS. Распакуйте архив полностью и запустите START.cmd. При первом запуске нужен интернет для установки зависимостей. Откройте http://localhost:3000. Останавливайте сервер сочетанием Ctrl+C.

Предоставленный ключ находится только в файле .env. Не публикуйте .env, не отправляйте архив с ключом другим людям. Для переноса проекта используйте .env.example и создайте новый серверный .env.

## Что работает
Регистрация и вход, серверные сессии в HttpOnly cookie, пароли с scrypt и случайной солью. Аккаунты, прогресс карточек и история разборов хранятся в SQLite в data/site.sqlite. Пользователь видит только свои данные. В профиле можно выйти, открыть и удалить разбор.

В разделе «Разбор работы» загрузите до четырёх фотографий. Gemini читает страницы без автоматического исправления ошибок ученика. Сравните текст с фотографиями, исправьте неточности и подтвердите его. После этого Gemini анализирует решение, объясняет конкретные ошибки и предлагает темы и упражнения. Можно ввести текст вручную. Локальный алгоритм диагностики и Tesseract больше не участвуют в этом разделе. Проверка готовых карточек с цифровым ответом сохранена.

Фотографии передаются в Google Gemini по запросу пользователя и не записываются сервером в базу. Текст и результат разбора сохраняются. Без входа доступны учебные материалы; запросы к нейросети требуют аккаунт.

## Настройки .env
GEMINI_API_KEY: ключ Google AI Studio.
GEMINI_OCR_MODEL: основная модель распознавания, gemini-3.5-flash-lite.
GEMINI_FALLBACK_MODEL и GEMINI_OCR_FALLBACK_MODEL: резервная модель, gemini-3.6-flash.
GEMINI_TIMEOUT_MS: 45000 мс на попытку, максимум две попытки с разными моделями.
GEMINI_ANALYSIS_THINKING: low по умолчанию, medium при необходимости.
GEMINI_MODEL: доступная модель с поддержкой изображений и структурированного ответа. По умолчанию gemini-3.5-flash-lite. Доступность зависит от аккаунта и региона.
PORT: порт, по умолчанию 3000.
HOST: 127.0.0.1 для локального запуска, 0.0.0.0 для контейнера.
COOKIE_SECURE: true для публичного HTTPS.
PUBLIC_ORIGIN: внешний адрес сайта за обратным прокси, например https://school.example.
DB_PATH: необязательный абсолютный путь к SQLite.

## Размещение
Это Node.js сервер с постоянным диском, а не статический сайт. Нужен VPS или контейнер с постоянным томом /app/data. Dockerfile включён. Передайте переменные окружения контейнеру; .env в образ не копируется. Настройте HTTPS на обратном прокси, PUBLIC_ORIGIN и COOKIE_SECURE=true. Не открывайте порт Node напрямую при размещении за прокси. Делайте резервные копии SQLite штатной командой VACUUM INTO или при остановленном сервере. Для нескольких серверных процессов потребуется общая БД и общее хранилище лимитов.

Почтовое восстановление пароля, подтверждение почты и панель администратора не реализованы. Существовавшие браузерные аккаунты автоматически не переносятся: создайте серверный профиль. Гостевой прогресс хранится локально и не объединяется с серверным. Перед публичным запуском определите порядок поддержки аккаунтов и удаления пользовательских данных.

## API
POST /api/auth/register {username,password,name}
POST /api/auth/login {username,password}
POST /api/auth/logout {}
GET /api/me
DELETE /api/me (удаляет аккаунт и связанные данные)
GET /api/progress
PUT /api/progress {grade,results}
POST /api/ocr {images:[data URL]}
POST /api/analysis {text,grade,confirmed:true}
GET /api/works (последние 100)
DELETE /api/works/:id
GET /api/health

Все изменения через JSON. Запросы выполняются с того же сайта. Сессия действует 7 дней. Ограничения: 30 запросов входа/регистрации за 15 минут на IP, 40 запросов к ИИ за час на аккаунт, 120 API-запросов за минуту на IP. Смена адреса модели пользователю через API недоступна. Ошибки сервиса не заменяются выдуманным разбором.

## Проверка
npm test проверяет регистрацию, вход, разделение данных, сохранение прогресса, выход, удаление аккаунта, защиту конфигурации, межсайтовые запросы, отклонение неподтверждённого текста и повреждённых изображений, ошибки провайдера и неправильный ответ модели.

Качество распознавания зависит от фотографии. Проверяйте сомнительные места перед анализом. Разбор одной работы не доказывает устойчивый пробел в знаниях.

Документация Gemini: https://ai.google.dev/gemini-api/docs/image-understanding и https://ai.google.dev/gemini-api/docs/structured-output

## Устойчивость ИИ
Черновик текста сохраняется в браузере отдельно для каждого аккаунта на семь дней. Фотографии в черновик не входят. После обновления страницы нужно заново подтвердить текст. При ошибке на очередной странице прочитанные страницы сохраняются; повторная попытка продолжает чтение. При ручной правке текста нужно подтвердить его полноту. При неполном распознавании кнопка разбора недоступна до исправления текста.

Одинаковые запросы одного пользователя объединяются. Успешное распознавание и готовый разбор кэшируются на сервере на сутки. Фотографии в кэш не записываются: сохраняются хэш и текст ответа. Ошибки, пустые и незавершённые ответы не выдаются за успешный разбор. При таймауте, перегрузке или некорректном ответе выполняется запрос к резервной модели. Ошибочный ключ не вызывает бессмысленные повторные попытки. В журнале есть этап, модель, длительность и статус без текста работы и ключа.
