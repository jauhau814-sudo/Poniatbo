# Понятно: сайт с сервером и Gemini

## Запуск на Windows
Установите Node.js 24 LTS. Распакуйте архив полностью и запустите START.cmd. При первом запуске нужен интернет для установки зависимостей. Откройте http://localhost:3000. Останавливайте сервер сочетанием Ctrl+C.

Предоставленный ключ находится только в файле .env. Не публикуйте .env, не отправляйте архив с ключом другим людям. Для переноса проекта используйте .env.example и создайте новый серверный .env.

## Что работает
Регистрация и вход, серверные сессии в HttpOnly cookie, пароли с scrypt и случайной солью. Аккаунты, прогресс карточек и история разборов хранятся в SQLite в data/site.sqlite. Пользователь видит только свои данные. В профиле можно выйти, открыть и удалить разбор.

В разделе «Разбор работы» загрузите до четырёх фотографий. Gemini читает страницы без автоматического исправления ошибок ученика. Сравните текст с фотографиями, исправьте неточности и подтвердите его. После этого Gemini анализирует решение, объясняет конкретные ошибки и предлагает темы и упражнения. Можно ввести текст вручную. Локальный алгоритм диагностики и Tesseract больше не участвуют в этом разделе. Проверка готовых карточек с цифровым ответом сохранена.

Фотографии передаются в Google Gemini по запросу пользователя и не записываются сервером в базу. Текст и результат разбора сохраняются. Без входа доступны учебные материалы; запросы к нейросети требуют аккаунт.

## Настройки .env
GEMINI_API_KEY: ключ Google AI Studio.
GEMINI_MODEL: доступная модель с поддержкой изображений и структурированного ответа. По умолчанию gemini-3.8-flash. Доступность зависит от аккаунта и региона.
PORT: порт, по умолчанию 3000.
HOST: 127.0.0.1 для локального запуска, 0.0.0.0 для контейнера.
COOKIE_SECURE: true для публичного HTTPS.
PUBLIC_ORIGIN: внешний адрес сайта за обратным прокси, например https://school.example.
DB_PATH: необязательный абсолютный путь к SQLite.

## Размещение
Это Node.js сервер с постоянным диском, а не статический сайт. Нужен VPS или контейнер с постоянным томом /app/data. Dockerfile включён. Передайте переменные окружения контейнеру; .env в образ не копируется. Настройте HTTPS на обратном прокси, PUBLIC_ORIGIN и COOKIE_SECURE=true. Не открывайте порт Node напрямую при размещении за прокси. Делайте резервные копии SQLite штатной командой VACUUM INTO или при остановленном сервере. Для нескольких серверных процессов потребуется общая БД и общее хранилище лимитов.

Почтовое восстановление пароля, подтверждение почты и панель администратора не реализованы. Существовавшие браузерные аккаунты автоматически не переносятся: создайте серверный профиль. Гостевой прогресс хранится локально и не объединяется с серверным. Перед публичным запуском определите порядок поддержки аккаунтов и удаления пользовательских данных.

## API
POST /api/auth/register {username,password,name}
POST /api/auth/login {username,password}
POST /api/auth/logout {}
GET /api/me
DELETE /api/me (удаляет аккаунт и связанные данные)
GET /api/progress
PUT /api/progress {grade,results}
POST /api/ocr {images:[data URL]}
POST /api/analysis {text,grade,confirmed:true}
GET /api/works (последние 100)
DELETE /api/works/:id
GET /api/health

Все изменения через JSON. Запросы выполняются с того же сайта. Сессия действует 7 дней. Ограничения: 30 запросов входа/регистрации за 15 минут на IP, 40 запросов к ИИ за час на аккаунт, 120 API-запросов за минуту на IP. Смена адреса модели пользователю через API недоступна. Ошибки сервиса не заменяются выдуманным разбором.

## Проверка
npm test проверяет регистрацию, вход, разделение данных, сохранение прогресса, выход, удаление аккаунта, защиту конфигурации, межсайтовые запросы, отклонение неподтверждённого текста и повреждённых изображений, ошибки провайдера и неправильный ответ модели.

Качество распознавания зависит от фотографии. Проверяйте сомнительные места перед анализом. Разбор одной работы не доказывает устойчивый пробел в знаниях.

Документация Gemini: https://ai.google.dev/gemini-api/docs/image-understanding и https://ai.google.dev/gemini-api/docs/structured-output
